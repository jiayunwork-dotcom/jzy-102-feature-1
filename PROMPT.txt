这套地形工具现在能造出一片噪声高度场、能对着一张高度图跑一轮雨滴侵蚀、也能把某一张算好的高度场连同参数起个名字存进内存里回头取回来。但它有个用起来别扭的地方：每次想让山脊再被多冲刷一点，都得让浏览器把整张高度数组发回后端、后端算完再整张发回来，后端自己一点都不记得这片地形被折腾到了第几步；而那些命名保存下来的结果彼此之间也是散的，谁先谁后、从谁演化来的，工具里没有任何交代。做科普演示时我们其实想要的是一条能一路推下去、还能倒回去重走的时间线，而不是一堆互不相干的静态截图。

请在现有后端上补一层由服务端自己掌管的「侵蚀演进」能力，把地形被反复冲刷的整个过程变成一条服务端记着的、有先后顺序的链，而不再靠前端来回搬运整张地图。演示者先用一张起始高度场开启一段这样的演进，拿到一个能一直引用它的标识；此后每让地形往前冲刷一轮，都由后端在它自己保存着的当前状态上接着算、把这一轮的结果作为新的一帧追加到这条链的末尾，前端只需要说一句「再推进一轮，用这组侵蚀参数」，不必也不该再把上一轮的高度数据回传一遍。这条链上的每一帧都应当能被单独取回来看，也能查到整条链现在走到了第几帧、每一帧当时用的是什么参数。

演进不能只能往前。演示者常常冲刷了几轮之后觉得某一轮的形态最好，想从那儿换一组参数再试试别的走向。所以要允许从这条链的任意一个历史帧岔出一条新的演进分支：新分支以那一帧的地形为起点独立往下走，它之后追加的帧只属于它自己，绝不能回头改动或污染原来那条链后续的任何一帧，两条链此后各走各的。哪一帧属于哪条链、某条链是从别的链的第几帧岔出来的，这些关系都要能被查询到。任何一帧都还应当能被导出成之前那种命名保存的静态结果，方便单独留档；反过来，演进链本身是服务端运行期间的活数据，进程重启后随内存一起丢掉是可以接受的，但只要进程还活着，链和它的每一帧、分支关系就必须稳定地存取得到。

比起单轮侵蚀，多轮连续冲刷真正值得看的是水最后往哪里汇。请在推进演进的过程中，持续维护一张和地形同样大小的「汇流量」场：对每个格点，它记的是顺着地表坡度一路汇下来、最终流经这个格子的水量总和。上游汇进来的越多，这个格子的数值越高，一条条河道就会在这张场上连成高值的脉络。这张汇流场要能随演进链一并取回，供前端把河网叠着地形画出来。它还要支撑一个判断：随着一轮轮往下冲，地形和它的水系会逐渐稳定下来，请让后端能够就某条演进链给出「是否已经收敛到河网稳态」的结论——依据是相邻两帧之间这张汇流场的整体变化幅度，当这个变化幅度小到某个阈值以下，就认为这条链已经趋于稳态，并把当前的变化幅度一并告知，好让演示者知道还差多少。

有几条关系必须钉死，并且要能被随仓库附带的自动化测试直接验证。其一，演进的可复现性要落到整条链上：对同一段演进从头按同样的参数序列、同样的随机种子逐轮重放，重放出来的每一帧都必须和原来逐比特一致，不允许「服务端自己记着状态」这件事引入任何不受种子控制的差异。其二，分支隔离要成立：从某历史帧岔出新分支并在新分支上继续推进若干轮之后，原链上那一帧及其之后的每一帧都必须原封不动，取回来和岔出之前完全相同。其三，汇流场要守恒且可解释：整张汇流场所有格点的数值加起来，应当等于这一轮里所有雨滴实际走过的步数之和（每一步都恰好给它当时所在格点贡献一次流经量），既不能凭空多也不能漏记，测试要能对着某一轮的实际雨滴步数把这个总量对上。其四，稳态判据要单调靠拢：在参数不变的持续推进下，相邻帧之间汇流场的整体变化幅度应当随轮次不增反降、一路收窄，直到跨过阈值被判为稳态，而不能出现越推越剧烈却仍报稳态这种自相矛盾的情形。

非法的用法要在动手算之前就挡回去，带原因返回错误而不是算到一半崩掉：引用一个并不存在的演进链或并不存在的帧、想从超出范围的帧序号岔分支、推进时给的侵蚀参数不合法，都应当被明确拒绝。原有的噪声生成、单轮侵蚀、命名快照、参数校验这些接口的既有行为不要改动，新的演进能力是在它们之上叠加的一层，与它们并存。原有那几条不变量（侵蚀率越大高度方差越大、固定种子逐比特可复现、一轮前后总高守恒）也仍要继续成立。

前端给这条演进链配一个够用的操作面：能开启一段演进、能对当前这条链一轮轮往前推并把最新地形刷新到三维画面上、能看到这条链已经走了多少帧并跳回任意历史帧查看、能从某一帧岔出新分支、能把汇流场以某种直观方式叠在地形上显示出来、能看到当前是否已判为稳态以及离稳态还差多少。不必做成复杂的版本树可视化，把这条链的帧序列和分支关系交代清楚、操作顺手即可。新增的服务端演进状态管理、汇流场计算、稳态判定各自拆成独立的后端模块，别一股脑塞进已有的那个侵蚀模拟类里；前端新增的演进操作与汇流场叠加显示也拆成独立组件，不要糊进原来的渲染或参数面板文件。整体仍旧用 Docker Compose 一并拉起、暴露同一个页面地址，随仓库附上覆盖上面四条关系的自动化测试。后端仍是 Java 17 配 Spring Boot，前端仍是 Vue 3 配 Three.js、用 Vite 构建。
